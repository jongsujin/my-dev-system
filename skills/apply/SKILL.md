# 리뷰 발견 적용

리포트의 줄 번호와 인용은 리뷰 시점 기준이다. 그래서 고치기 전에 스크립트로 지금 코드와 대조하고, 분류 결과대로만 고친다.

## 1. 계획 세우기

레포 루트에서 실행한다. 사용자가 리포트 경로나 옵션(`--auto-major`, `--with-minor`)을 주면 그대로 넘긴다.

```bash
node <이 스킬 폴더>/scripts/apply-plan.mjs [report.json] [--auto-major] [--with-minor]
```

종료 코드가 0이 아니면 메시지를 그대로 전하고 멈춘다. 리포트를 생략하면 가장 최근 리포트를 쓴다.

## 2. 미리보기

출력을 가공하지 않고 보여 준다. "주의" 경고가 있으면 계속할지 먼저 묻는다.

## 3. 바로 적용

항목마다:
1. 표시된 파일의 해당 줄을 읽는다.
2. 그 자리 안에서만 한 번의 편집으로 `fix`를 반영한다.
3. `node <이 스킬 폴더>/scripts/apply-plan.mjs mark <report> <id> applied`

한 자리 교체로 끝나지 않는 수정이면 억지로 하지 말고 확인 후 적용 목록으로 옮긴다.

## 4. 확인 후 적용

한 번에 번호를 붙여 보여 준다. 근거가 어긋났거나(drift) 여러 곳에 있으면(ambiguous) 후보 줄을, 겹치는 항목은 두 제목을 함께 적는다. 그리고 묻는다: "전부 / 번호 선택 / 아니요". 고른 것은 3번처럼 적용하고, 나머지는 `mark <report> <id> skipped`.

## 5. 안내만 · 적용하지 않음

목록과 이유만 보여 준다. 고치지 않는다.

## 6. 마무리

- `.harness.json`의 `verify.commands`를 실행하고 실제 결과를 보고한다.
- `git diff --stat`을 보여 준다.
- 적용·건너뜀·적용하지 않음 수를 요약한다.
- 커밋하지 않는다.

## 안전 규칙

- 새 파일을 만들지 않는다.
- 보호 파일(`review.protect`, 기본은 패키지 매니페스트·잠금 파일·마이그레이션·`.harness.json`)은 발견이 요구해도 고치지 않는다.
- 발견이 가리킨 자리 밖의 코드는 건드리지 않는다.
- 근거가 정확히 일치하지 않는 항목은 사용자가 고르기 전에는 적용하지 않는다.
