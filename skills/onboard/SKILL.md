# 기존 프로젝트 온보딩

목표: 새로 합류한 사람이 하루 안에 "실행하고, 고치고, 검증할 수 있는" 상태가 되게 한다. 추측으로 채우지 않고, 명령은 실제로 돌려 본 것만 적는다.

## 1. 조사 (read-only)

`planner` 서브에이전트에 맡기거나 직접 확인한다.

- **스택**: 패키지 매니저(lock 파일), 언어·프레임워크, 런타임 버전(`.nvmrc`, `.tool-versions`, `engines`).
- **명령**: `package.json` scripts, `Makefile`, `justfile`, CI 설정(`.github/workflows`)에서 실행·린트·타입 검사·테스트 명령을 찾는다. **CI가 실제로 돌리는 명령이 진짜 기준**이다.
- **구조**: 진입점, 라우팅, 데이터 접근 계층, 공용 모듈. 디렉터리 지도는 한 단계 깊이까지.
- **규칙 문서**: 기존 `README`, `CONTRIBUTING`, `AGENTS.md`, `CLAUDE.md`, ADR.
- **위험 영역**: 결제·인증·권한·데이터 삭제·외부 발송·배포 스크립트·크론. 파일 경로로 표시한다.
- **환경**: 필요한 환경변수 이름(값은 읽거나 출력하지 않는다), 로컬에 필요한 DB·서비스.

## 2. 검증 명령 실제로 돌려 보기

찾은 린트·타입 검사·테스트 명령을 각각 실행한다. 각 명령에 대해 기록한다:
- 성공/실패, 걸린 시간
- 실패면 원래부터 실패하는 것인지 (기본 브랜치 기준) — 이것이 **베이스라인**이다

10분 넘게 걸리거나 외부 자원(운영 DB 등)이 필요한 명령은 실행하지 않고 그 이유를 적는다.

## 3. 산출물 제안

사용자 확인을 받고 만든다. 이미 있는 파일은 덮어쓰지 않고 차이를 보여 준다.

1. **`docs/ONBOARDING.md`**: 한 페이지. 실행 방법 / 명령 표(베이스라인 포함) / 디렉터리 지도 / 위험 영역 / 처음 읽을 파일 5개 / 모르는 것 목록.
2. **`.harness.json`**: 플러그인 `templates/harness.json`을 바탕으로, 2단계에서 통과한 명령만 넣는다.
   - `onEdit`: 파일 하나에 빠르게 도는 린트 (예: `npx eslint {file}`)
   - `onStop`: 1분 안쪽 명령 (린트·타입 검사)
   - `onCommit`: 타입 검사
   - 베이스라인이 빨간 명령은 넣지 않거나 `gates.block: false`(안내 모드)로 시작한다고 제안한다
   - `context.rules`: 스택에 맞게 (`typescript`, `react` 등)
   - `guard.deny`: 위험 영역에서 찾은 운영 접속 문자열 패턴 (예: 운영 DB 호스트)
3. **`AGENTS.md`**: 레포에 없으면 플러그인 `templates/AGENTS.md`를 채워 제안. 있으면 빠진 항목(명령·금지 사항)만 제안. Claude Code용 `CLAUDE.md`에는 `@AGENTS.md` 한 줄.

## 4. 마무리

- 다음 세션부터 하네스가 무엇을 하는지 세 줄로 설명한다 (규칙 주입, 편집 직후 검사, 완료 전 검증).
- "모르는 것 목록"은 사람에게 물어볼 질문으로 정리해 준다.
